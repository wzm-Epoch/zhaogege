# 负责人指南

## 发布任务

1. 在 [Issue 表单入口](https://github.com/wzm-Epoch/zhaogege/issues/new/choose) 选择“作业发布”。
2. 指定唯一作业编号，例如 `task-001`。编号以英文字母或数字开头，仅使用英文字母、数字、短横线和下划线。
3. 填清任务要求、提交内容、验收标准和截止时间（含时区，或明确不设截止时间）。需要长期保留的详细说明可放在 `assignments/作业编号/README.md`。
4. 将任务链接发给成员。每人通过独立目录和 PR 提交，个人 PR 使用 `Refs #编号` 关联任务，避免提前关闭任务。

## 审核 PR

- 确认是成员自己的目录，附件和说明完整，无意外覆盖他人内容。
- 查看“文档与提交检查”的结果，再检查作业内容和引用来源。自动检查不代表作业已通过验收。
- 涉及程序时，先阅读代码，再在合适的隔离环境中按说明验证；此仓库的自动流程不运行成员程序。
- 需要补充时，在 PR 中给出具体修改意见。成员更新原分支后再次检查，符合要求再合并。
- 全体提交和讨论处理完毕后，由负责人关闭任务 Issue。

## 自动检查的范围

执行 `python scripts/check_repository.py` 会检查：

- Markdown 中内联格式的本地链接和图片是否有对应文件（跳过代码块、行内代码和外部链接）；
- 作业编号与个人目录命名、个人目录是否包含非空 `README.md`；
- 单个文件是否超过 10 MiB，以及常见依赖或缓存目录是否被误提交。

链接检查不联网，不检查外部网址是否可用，也不检查标题锚点或 Markdown 引用式链接。`.gitignore` 只是减少误提交，不是凭据扫描器。

## GitHub 设置建议

当前协作约定是“PR 提交、负责人合并”。如需技术上限制直接推送，可在仓库 **Settings → Rules → Rulesets** 中为 `main` 配置必须经过 PR、负责人审核和状态检查。先确保“文档与提交检查”已实际运行，再选择对应检查；审核人数和绕过权限按实际负责人数量配置，避免无人能够合并。

本次文件优化没有开启分支保护，也没有调整成员权限。Issues 已能满足当前交流需要；后续话题增多时，再考虑开启 Discussions。
