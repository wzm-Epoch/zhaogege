# 作业提交与学习交流优化方案

用户已确认采用“成员提交 PR，负责人检查后合并”的方案。

## 范围

保留现有学习笔记目录及历史文件；补齐中文导航、网页提交教程、个人作业目录规范、周总结模板、PR 模板和三类 Issue 表单。使用 Issues 进行任务发布、提问和资源分享，不依赖 Discussions。

作业位于 `assignments/作业编号/GitHub用户名/`；周总结位于 `ai-learning-notes/每周分享总结/YYYY-MM-DD/GitHub用户名.md`。不同成员使用独立文件，个人 PR 使用 Refs 关联任务。

## 检查与边界

通过只读权限的 GitHub Actions 执行仓库规范检查：本地文档链接、作业目录、说明文件、文件大小与依赖缓存目录。不执行成员作业，不判断答案、评分或截止时间，不更改成员权限及分支保护。

检查失败时输出具体文件和原因，成员更新同一 PR。负责人结合检查结果人工验收后合并。

## 实施与验收

1. 补齐导航、提交与维护说明及内容模板。
2. 添加 Issue 表单、PR 模板和忽略规则。
3. 实现标准库检查脚本与自动流程。
4. 验证所有本地链接、YAML 结构及有效和无效作业样例，检查最终远程差异。

不创建虚构任务、成员、历史总结、评分或截止时间。
